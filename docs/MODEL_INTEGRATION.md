# Алгоритм PCBA и следующий шаг с моделью аномалий

## Текущий реализованный способ

Reference-based comparison в `backend/inspection.py`:

1. Уменьшение растров до ограниченного размера.
2. SIFT-признаки на снимках с выравниванием контраста и поиск соответствий.
3. Homography с RANSAC, контроль числа/доли согласованных точек, их распределения, формы преобразования и reprojection error.
4. Перенос исправного эталона в координаты проверяемого снимка, построение маски сопоставимой области.
5. Нормализация общего света в Lab, локальная SSIM-подобная структурная карта и цветовая разность.
6. Порог, морфология и связные области, фильтр по площади.
7. Возврат координат, карты различий, совмещённого эталона и показателей качества.

Автоматически указывается только наличие визуального отличия. Названия вроде «Отсутствующий компонент» выбирает мастер. Изменения могут быть нормальной маркировкой, бликом или допустимой вариацией. Это не реализация чужой обученной ChangeChip-модели и не новая нейросеть.

Справка по методу геометрии: [OpenCV SIFT и homography](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html). Исследование подхода со сравнением эталона: [ChangeChip](https://arxiv.org/abs/2109.05746). Собственный код проекта опубликован под MIT, код из ChangeChip не копировался.

## Конфигурация

`config/inspection.json`:

| Поле | Назначение |
|---|---|
| max_side | Максимальная сторона рабочего растра |
| default_threshold | Начальный порог карты |
| min_inliers / min_inlier_ratio | Минимум соответствий, согласованных с homography |
| min_feature_coverage | Минимальная доля площади convex hull опорных точек на каждом снимке |
| min_coverage_for_pass | Минимальное покрытие выбранной области эталоном, по умолчанию 92% |
| max_changed_fraction | Слишком большая доля изменений блокирует PASS |
| max_regions | Ограничение количества рамок; при усечении PASS блокируется |

Числа — инженерные начальные пороги, не результаты валидации на ваших платах. Изменение конфигурации требует перезапуска. Хеш конфигурации сохраняется в отчёте для воспроизводимости.

Настраивайте на отдельном validation-наборе, не на итоговом тесте. Если одинаковые исправные платы дают рамки, сначала исправьте свет и ракурс. Сильное увеличение порога просто скрывает небольшие дефекты.

Один плоский homography не исправляет параллакс высоких компонентов при изменении ракурса. Снимайте сверху с фиксированной камеры. Проверяемый снимок и эталон должны содержать ту же допустимую комплектацию.

## Как добавить обучаемую модель аномалий

Следующий вариант — PatchCore / PaDiM / EfficientAD на нормальных снимках конкретной модели платы. В этой сборке такая модель **не обучена и не подключена**. Чтобы её добавить:

1. Соберите нормальные фото одного-двух видов PCBA с вашей камеры, с допустимыми вариациями. Разделяйте обучение и проверку по физическим платам и сессиям съёмки.
2. Соберите отдельные дефектные случаи для валидации и окончательного теста. Датасет VisA полезен для исследования, но не заменяет снимки вашей платы.
3. Обучите выбранный метод и сохраните всю модель/банк признаков и преобразования. Нужны веса и параметры нормализации карты, а не только ImageNet-backbone.
4. Добавьте новый backend с контрактом API из `API.md`. Должны возвращаться карта аномалий, координаты на проверяемом снимке, версия модели и флаги непроверенных участков.
5. Не выдавайте raw anomaly score за вероятность. Порог подбирайте на validation, оцените пропуски и ложные тревоги отдельно на final test.
6. Если классификация причины не обучалась, сохраняйте нейтральное «Подозрительный участок». Для дефектов пайки нужен отдельный датасет/крупная съёмка и соответствующая модель.

UI, история v2 и экспорт уже отделяют `anomaly_score` от `score`, исходный вывод алгоритма от решения мастера и ручной диагноз от автоматической находки. Новый backend можно подключить без переписывания формата истории.

## Что проверить перед использованием

Сначала пройти `WINDOWS_CHECKLIST.md` и включённые тесты. Затем собрать независимую выборку с реальными нормальными/дефектными платами. Измерять recall по нужным типам дефекта, false alarms на исправных платах и полный цикл мастера. На текущем этапе таких измерений не проводилось.
