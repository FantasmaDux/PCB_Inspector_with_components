# PCB Inspector PCBA

Локальный прототип визуального контроля **платы с установленными компонентами**. Проверяемый снимок сравнивается с исправным эталоном той же модели, ревизии и комплектации. Сохранены светло-серый интерфейс с зелёными элементами, ручная разметка, история, JSON, снимки с рамками и печать в PDF.

**Реализованный метод:** OpenCV SIFT + RANSAC для совмещения, нормализация освещения, карта структурных и цветовых отличий. Это reference-based computer vision, а не обученная нейросеть для классификации дефектов. Веса предыдущей модели для плат без компонентов здесь не используются. Отмеченные отличия могут соответствовать отсутствию/смещению компонента или видимому повреждению, но диагноз подтверждает мастер.

## Запуск на Windows

Цель: Windows 10/11 x64, рекомендуемый Python 3.12 x64, Edge или Chrome. Для обработки используется CPU. CUDA, видеокарта, Node.js и ключи API не нужны.

1. Полностью распакуйте `PCB_Inspector_PCBA_Windows.zip`, например в `C:\Projects\PCB_Inspector_PCBA`.
2. Установите [Python 3.12 x64](https://www.python.org/downloads/windows/), добавьте Python в PATH / установите Python Launcher.
3. Запустите `setup_windows.bat`. Он создаст `.venv-win`, установит numpy, Pillow и OpenCV. Первая установка требует интернета.
4. Запустите `start_windows.bat`. Откройте **http://127.0.0.1:8765**. Окно сервера оставьте открытым. Остановка — Ctrl+C.

Если порт занят: `start_windows.bat --port 8766`, затем http://127.0.0.1:8766 . При DLL-ошибке OpenCV установите актуальный Microsoft Visual C++ x64 runtime. Скрипты `.bat` имеют CRLF и не зависят от путей исходного Mac.

**Запуск приложения, сравнение изображений и интерфейс в этой версии не проверялись на хосте автора по договорённости.** Проведены статические проверки исходников и состава архивов. Алгоритмические и API-тесты включены для запуска на вашем Windows-ПК, а не объявлены пройденными. См. `docs/WINDOWS_CHECKLIST.md`.

## Сценарий проверки

1. В блоке **«Исправный эталон»** загрузите чёткое фото заведомо исправной платы. Укажите модель и ревизию. Убедитесь, что комплектация совпадает, и поставьте соответствующую галочку. Пустое посадочное место может быть штатной особенностью сборки.
2. Загрузите фото проверяемой платы. Снимайте примерно сверху, при похожем свете и масштабе. Перекрытия, сильный наклон, большие изменения высоты камеры и блики ухудшают сравнение.
3. При необходимости выделите прямоугольную область проверки. Например, один узел платы без наклеек и серийного номера. PASS будет относиться **только к этой области**, не ко всему устройству.
4. Нажмите **«Сравнить с эталоном»**. Алгоритм использует реальные пиксели двух снимков, а не название файла или готовые ответы.
5. Переключайте вид: проверяемая плата, совмещённый эталон, карта отличий, наложение 50/50. На карте серым отмечены участки выбранной области без покрытия эталоном.
6. Найденные области первоначально имеют тип **«Визуальное отличие»**. Подтвердите или отклоните каждую находку. При желании укажите тип вручную. В отчёте будет видно, что его назначил мастер, а не алгоритм.
7. Пропущенный дефект можно отметить вручную рамкой. После проверки находок и остальных участков подтвердите завершение осмотра.
8. Сохраните историю, скачайте JSON или снимок с рамками. Для PDF нажмите «Печать / PDF» и выберите сохранение в браузере.

## Настройки и ограничения

- **Порог различий** — от 0.10 до 0.90, по умолчанию 0.40. Меньше порог — больше подозрительных участков и ложных тревог. Это не вероятность дефекта и не нейросетевая уверенность.
- **Минимальная площадь** — размер связной области изменений в пикселях рабочего снимка. По умолчанию 40 px. Мелкие изменения ниже этого размера не показываются. Для другой камеры/масштаба параметр нужно подбирать.
- При загрузке снимки уменьшаются до 1600 px по длинной стороне. Координаты отчёта относятся к этому растру. Для мелкой пайки нужны крупные снимки отдельных узлов, а не общий план огромной платы.
- Новый порог и площадь применяются после повторного сравнения. Изменение эталона, снимка, ревизии или ROI сбрасывает текущий результат и подтверждения.
- Шкала карты различий 0..1 описывает локальное структурное/цветовое расхождение. Высокое значение может быть вызвано бликом или другой маркировкой.
- Не определяются электрическая исправность, скрытые контакты BGA, внутренние трещины и невидимые дефекты. Диагноз пайки по общему снимку не гарантируется.

## PASS, FAIL и качество совмещения

Окончательный результат формируется с участием мастера:

- **FAIL** — мастер подтвердил хотя бы один видимый дефект. Даже если автоматическая проверка неполная, это отдельно отражается в результате и JSON.
- **Нужна проверка** — есть неразобранные находки либо мастер не завершил осмотр.
- **Нужна пересъёмка** — совмещение не получилось, эталон недостаточно покрывает область, слишком много отличий или снимок размыт. Такой результат **не может автоматически стать PASS** после отклонения всех рамок.
- **PASS** — автоматическое сравнение не заблокировано, находки разобраны, подтверждённых дефектов нет и мастер подтвердил завершение. Это итог визуального осмотра выбранной области с данным эталоном.

В режиме ручной разметки без выполненного сравнения отчёт явно указывает `MANUAL`. Алгоритм не проверяет название платы и её BOM: совпадение ревизии/комплектации подтверждает пользователь. Значения контроля качества являются инженерными порогами, пока не откалиброванными на ваших платах.

## История и перенос отчётов

История PCBA хранится в новом ключе `pcb-inspector-pcba-history-v2` в `localStorage`. При первом открытии она копируется из прежнего `pcb-inspector-history-v1`, если записи доступны. Оригинальные записи v1 остаются в своём хранилище. При том же браузере и адресе `http://127.0.0.1:8765` они открываются как архив старого режима. `localhost` и `127.0.0.1`, а также разные порты — разные хранилища браузера.

История не переносится вместе с папкой или Git. Для другого ПК скачайте JSON и в новой сборке откройте **«История осмотров → Импорт JSON»**. Поддерживаются старые отчёты v1 и новые v2. Новая запись хранит оба снимка, версию алгоритма и хеш конфигурации, ROI, качество совмещения, карту отличий и решения мастера.

Максимум 20 записей, но память браузера может закончиться раньше из-за снимков. Приложение сообщает об ошибке, не притворяясь, что сохранило запись. Для длительного хранения используйте JSON.

## Демонстрационные данные и реальные платы

В Windows-архив входят небольшие **синтетические иллюстрации** сборки: норма, удалённый условный компонент, смещение с поворотом кадра. Это не реальные фотографии и не доказательство качества. Исходник генератора — `scripts/make_demo.py`.

После клонирования Git или распаковки Source-архива установщик создаст эти примеры автоматически. Нейросетевые веса не скачиваются. Обучающий датасет для запуска reference-сравнения не требуется: нужен исправный эталон.

Где взять реальные исследовательские данные и как перейти к обучаемой модели аномалий: `docs/DATASETS.md` и `docs/MODEL_INTEGRATION.md`. Данные с неопределёнными условиями распространения в публичный Git не включены.

## Файлы и работа с кодом

```text
frontend/index.html              разметка интерфейса
frontend/styles.css              тема, адаптивность и печать
frontend/app.js                   загрузка пары, рамки, история v1/v2, отчёты
backend/server.py                 HTTP и проверка входных данных
backend/inspection.py             совмещение и анализ отличий
config/inspection.json            параметры качества и пороги алгоритма
samples/                         синтетические пары, без настоящих пользовательских плат
scripts/windows_launcher.py       установка и запуск под Windows
scripts/check_installation.py     проверка зависимостей без запуска сервера
scripts/make_demo.py              генератор примеров
scripts/package_project.py        сборка архивов с исключением локальных данных
tests/                           алгоритмические и API-проверки для целевого ПК
docs/                            API, ограничения, данные и контрольный сценарий

start_windows.bat                 запуск
```

HTML/CSS/JS можно редактировать и обновлять страницу без сборщика. После изменения Python или конфигурации перезапустите сервер. Корень проекта определяется через `__file__`, поэтому путь распаковки произвольный.

## Git и конфиденциальность

Исходники подготовлены для Git: `.gitignore`, `.gitattributes` и MIT LICENSE. Чтобы создать репозиторий:

```sh
git init
git add .
git status
git commit -m "Add PCBA reference inspection prototype"
```

Удалённый репозиторий не создавался, публикация не выполнялась. Ключей API, учётных данных и привязки к исходному пользователю в комплекте нет. `local_data/`, `private/`, `reports/`, `.env`, окружения и служебные файлы исключены из Git. Архиватор дополнительно включает только разрешённые каталоги исходников.

Храните настоящие фотографии и отчёты в `local_data/` или `reports/`. Не помещайте их в `samples/`, `docs/` и другие каталоги, предназначенные для публикации. Снимки обрабатываются локально, внешних API анализа нет. Браузерные отчёты содержат сами изображения — учитывайте это при передаче JSON.

## Офлайн-установка и проверки

Для работы после установки интернет не нужен. Чтобы установить на ПК без интернета, заранее на Windows с той же архитектурой и версией Python скачайте зависимости:

```bat
py -3.12 -m pip download --only-binary=:all: -r requirements.txt -d wheelhouse
```

Перенесите `wheelhouse`, установщик Python и нужный Visual C++ runtime вместе с проектом, затем выполните `setup_windows.bat --offline`. `wheelhouse` не включается в обычные архивы автоматически.

На целевом ПК:

```bat
.venv-win\Scripts\python.exe -m unittest discover -s tests -v
```

Пошаговая ручная проверка: `docs/WINDOWS_CHECKLIST.md`. Текущая версия не объявляется прошедшей Windows-тестирование до этого прогона.
