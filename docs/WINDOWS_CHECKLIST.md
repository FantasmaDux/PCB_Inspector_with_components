# Первая проверка на Windows

Статус сборки: код и архивы проверены статически. HTTP-приложение, UI и алгоритмические тесты на хосте автора не запускались. Отдельной гарантии запуска Windows нет до этого прогона.

1. Распаковать Windows-архив, установить Python 3.12 x64 и выполнить `setup_windows.bat`. Проверить, что нет ошибок установки и OpenCV содержит SIFT.
2. Запустить `start_windows.bat`, открыть `http://127.0.0.1:8765` в Edge/Chrome. При ошибке сохранить текст консоли целиком.
3. Выбрать встроенную пару «Без внесённых изменений». Убедиться, что загружены два снимка и видно предупреждение о синтетическом примере. Запустить сравнение. Не должно быть автоматического окончательного PASS без подтверждения мастера.
4. Выбрать «Удалён условный компонент». Проверить карту и рамки, подтвердить одну находку. Итог должен стать FAIL.
5. Отклонить находки, завершить осмотр. PASS допустим только если качество сравнения не заблокировано. Отдельно проверить плохой/пустой эталон: пустой список рамок при ошибке не должен давать PASS.
6. Переключить проверяемый снимок, совмещённый эталон, карту и наложение. Координаты рамок должны совпадать с проверяемой платой во всех видах.
7. Выделить ROI и повторить сравнение. В отчёте проверить выбранную область и её покрытие. Затем сбросить ROI.
8. Добавить дефект вручную, выбрать тип, скачать PNG и JSON. Ручная находка не должна получить выдуманную вероятность.
9. Сохранить историю, обновить страницу, открыть запись. Эталон, снимок, карта, ROI, типы и решения должны восстановиться. Проверить изменение статуса и повторное сохранение.
10. Импортировать JSON в историю другого браузера. При наличии старого JSON v1 проверить, что запись открывается как архив прежнего режима и не называется PCBA-сравнением.
11. Создать PDF через печать. Проверить номер платы, ревизию, снимки, результат, предупреждения и координаты. PDF может занимать несколько страниц.
12. Загрузить настоящую исправную плату и её эталон при фиксированном свете. Затем проверить подтверждённые дефекты. Подобрать параметры на отдельном наборе и записать ложные тревоги/пропуски.

Автоматические проверки после установки:

```bat
.venv-win\Scripts\python.exe -m unittest discover -s tests -v
```

`test_inspection.py` сравнивает синтетические данные и проверяет геометрию/ограничения; `test_api.py` поднимает временный локальный сервер для ошибок API. Это не оценка качества на настоящих платах. Если алгоритмический тест падает, сохранить traceback и параметры окружения, а не объявлять сборку проверенной.
