# API PCBA v2

Сервер по умолчанию доступен на `http://127.0.0.1:8765`. Внешние сервисы анализа не вызываются. Размер POST до 24 МБ, каждый исходный снимок до 20 мегапикселей. Браузер уменьшает снимки до 1600 px по длинной стороне.

## GET /api/health

Версия приложения и объект `model` с `ready`, `name`, `version`, `method='reference_cv'`, `requires_reference=true`, `provider='OpenCV CPU'`, `config_sha256`, `default_threshold`, `error`, `classes` и `labels_ru`.

Название поля `model` сохранено для совместимости с форматом отчётов и UI v1. В PCBA оно описывает алгоритм, а не нейросеть и не ONNX-веса. В `classes` перечислены типы, доступные мастеру; автоматическая находка всегда `visual_difference`.

## GET /api/samples

Список синтетических пар: `file`, `reference`, `label`, `variant`, `synthetic=true`, `description`. Их названия и описания используются только в интерфейсе выбора; в анализатор не передаются.

## POST /api/analyze

```json
{
  "image": "data:image/jpeg;base64,...",
  "reference": "data:image/jpeg;base64,...",
  "variant": "Controller-A rev.2",
  "same_board_confirmed": true,
  "threshold": 0.4,
  "min_area": 40,
  "roi": null
}
```

- `image`, `reference` — JPEG, PNG или WebP как base64 data URL.
- `variant` — непустое обозначение платы и ревизии до 120 символов. Это сведения пользователя, не результат распознавания маркировки.
- `same_board_confirmed` — именно `true`, иначе 400.
- `threshold` — конечное число 0.10–0.90.
- `min_area` — целое число 8–10000, px² рабочего снимка.
- `roi` — `null` для всего снимка или `[x1,y1,x2,y2]` в нормированных координатах 0–1 проверяемого снимка. Размер по каждой стороне не меньше 0.02.

Основные поля ответа:

| Поле | Значение |
|---|---|
| detections | Список подозрительных областей |
| box | xyxy, px рабочего проверяемого снимка |
| class_name / label | visual_difference / Визуальное отличие |
| anomaly_score | Индекс отличия 0–1, не вероятность дефекта |
| score | null, чтобы не выдавать индекс за нейросетевую уверенность |
| status | pending, решение мастера ещё не принято |
| machine_verdict | Предварительные PASS, FAIL или REVIEW |
| analysis_blocked | При true UI не может выставить PASS |
| analysis_available | Выполнены совмещение и анализ отличий |
| alignment | Метод, матрица в рабочих координатах, количество и доля inliers, покрытие точками, медианная ошибка |
| coverage | Доля выбранной области, покрытая эталоном, 0–1 |
| changed_fraction | Доля изменившихся пикселей в сопоставимой области |
| warnings | Причины ограничения надёжности |
| aligned_reference / heatmap | JPEG data URL в системе координат проверяемого снимка |
| reference_sha256 / inspection_sha256 | SHA256 RGB-растра, не исходного JPEG-файла |
| elapsed_ms | Совмещение, карта, postprocess и подготовка артефактов, без времени мастера и HTTP |

При сбое совмещения возвращается HTTP 200 с `machine_verdict='REVIEW'`, `analysis_blocked=true`, `analysis_available=false`, пустыми detections и объяснением. Пустой список при таком ответе **не означает отсутствие дефектов**.

400 — неверный запрос, 403 — запрещённый Origin, 404 — файл/маршрут не найден, 413 — слишком большой запрос, 503 — нет OpenCV, 500 — ошибка вычисления. Сервер никогда не заменяет ошибку на PASS.

## JSON-отчёт v2

Создаётся в UI и содержит оба снимка, ROI, параметры, метаданные алгоритма, совмещение, хеш конфигурации, предупреждения, первоначальный индекс отличия, ручной тип и решения мастера. Ручная классификация помечается `master_classified=true`, найденный вручную участок — `source='manual'`.

`verdict` — итог мастера, `machine_verdict` — предварительный итог алгоритма, `master_completed` — завершён ли весь осмотр. FAIL может быть сохранён при незавершённом осмотре, если уже подтверждён дефект. Исторические v1-отчёты открываются с пометкой прежнего режима.
